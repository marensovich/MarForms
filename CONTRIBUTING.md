# Как участвовать

Спасибо, что помогаете MarForms. Коротко о том, как у нас принято.

## Перед началом

- Задача есть в [Issues](https://github.com/marensovich/MarForms/issues) или согласована с
  владельцем. Крупное изменение сначала обсуждаем в задаче.
- Требования — в [ТЗ](docs/spec/business-requirements.md), экраны — в
  [макетах](docs/design/README.md). Интерфейс делается точь-в-точь по ним.
- Google Sheets и платные тарифы сейчас заморожены.

## Разработка

Как поднять проект — в [README](README.md#быстрый-старт).

- Ветка от `master`: `feat/…`, `fix/…`, `docs/…`.
- Код пишется так же, как написан соседний: те же имена, комментарии и приёмы.
- Новая колонка или таблица — только новой миграцией Flyway (`V<N>__что_делает.sql`), старые
  миграции не меняются.
- Новый текст интерфейса — в оба перевода: `frontend/public/locales/ru` и `en`.
- Поведение покрыто тестом: бэкенд — JUnit/MockMvc, фронтенд — Vitest + Testing Library.

## Перед пул-реквестом

```bash
cd backend && ./gradlew test
cd frontend && npm test && npm run lint && npm run build
```

- Коммиты в стиле [Conventional Commits](https://www.conventionalcommits.org/ru/):
  `feat: …`, `fix: …`, `docs: …`. Заголовок говорит, что изменилось для пользователя.
- В описании PR: что и зачем, как проверить, ссылка на задачу (`Closes #123`).
- CI должен быть зелёным.

## Лицензия

Код проекта не open source (см. [LICENSE](LICENSE)). Отправляя изменения, вы соглашаетесь, что
они становятся частью проекта на тех же условиях.
